## 2. 第一轮从这里开始

**第一件事：读 01 的第 1—4 节。** 把“用户请求 → 查询 → 提案 → 审批 → 执行 → 校验”的流程画出来，标出模型、Loop、RunManager、Gateway 和数据库各自负责什么。

**第二件事：回答 V03、V05、V07、V08、V13。** 暂时合上答案，用自己的话说。遇到说不清的地方只回到对应函数，不从头浏览整个仓库。

**第三件事：完成 L01、L02。** 先确认环境，再运行选定离线用例。观察消息变化、工具执行次数和最终状态，说明预期与实际是否一致。

这一轮的通过标准：能解释为什么模型知道上次查到了什么；能说明模型输出创建日程调用时，外部世界为何还没变化；能指出批准后从哪个入口继续。完成后再进入审批、并发和恢复。

## 4. 每道题怎样用

1. **先答 30—90 秒**：给核心结论、一个机制、一条边界。
2. **再画具体状态**：消息增加什么，哪一行记录改变，外部系统发生什么。
3. **接受一个追问**：超时、重启、重复、版本变化或恶意输入出现时怎么办。
4. **最后找证据**：函数、SQL 条件、测试断言、运行记录。没跑过的标注“只读过代码”。

例如回答“如何避免重复操作”，不能停在“幂等键”。应继续说明键在哪个作用域稳定、谁原子认领、回执保存在哪、外部成功但本地没有记录时如何查询，以及什么情况下仍然无法确定。

## 5. 回答前先分清的几个词

| 词 | 在学习中先记住的含义 |
|---|---|
| Tool Call | 模型提出工具名和参数；实际执行由程序控制 |
| Observation | 工具返回的可观察结果，带来源；不自动成为可信指令 |
| Proposal / Approval / Receipt | 准备做什么 / 谁批准了什么 / 实际执行与核验结果 |
| Run / Task / Attempt | 一次运行 / 一项工作 / 工作的某次尝试；项目中的具体定义见架构文档 |
| Idempotency | 重复逻辑请求在定义好的边界内不重复产生业务效果，不是“随便加 UUID” |
| Lease | 有期限的执行权；过期不等于旧进程停止 |
| Checkpoint | 为恢复保存的状态；能恢复哪些边界取决于保存了什么、适配器需要什么 |
| Skill | 可复用的过程指令及相关契约；启用版本不等于训练模型权重 |
| Held-out | 没有用于产生/调试候选的独立评测样本；仍需审视相似任务泄漏 |
| Oracle | 判断任务是否满足要求的标准或验证器；不等于模型自己说成功 |
| Artifact Version | 固定的交付内容版本，与继续编辑中的 LIVE 文档区分 |
| Reconciliation | 根据持久记录和外部事实核对结果，解决或保留不确定状态 |

## 6. 哪些回答优先练熟

先能回答以下问题，再追求题量：

- 一个完整任务怎样执行，控制权在哪里转移？
- 为什么要把查询和外部写入分开？审批究竟绑定什么？
- 外部成功但本地超时，为什么不能直接重试？
- 当前所谓恢复包括哪些范围，哪些还没有接通？
- Knowledge、Memory 和 Skill 的读写来源如何区分？
- Skill 候选怎样评测，为什么接受不等于启用？
- 两个 Worker 如何竞争任务，旧 Worker 恢复后怎么办？
- 测试、评审、最终代码版本如何对应？
- 为什么 Worktree 与 Yjs 都不能替代业务验收或执行隔离？
- 当前缺点是什么，下一步如何用实验验证改进？
- AI 辅助写了哪些代码，你本人真正解释和验证过哪些部分？
- 为什么现有记录不能证明 Skill 或多 Agent 一定带来收益？
