# 补习地图：具体学什么、学到什么程度

核查日期：2026-09-22。适用目标：中国大陆社招 AI 应用 / Agent 开发。本文是学习要求，不是对 Sid 当前熟练程度的认定。

你已有 Java 后端、C++/Linux 工作经历和 MySQL 使用基础；Python 需要优先补，TypeScript/Node.js、PostgreSQL、SQLite 尚需结合项目学习。两个项目包含的技术不等于你已经掌握的技术。读书按你自己的节奏进行，这里只安排项目与求职需要的练习。

## 1. 如何判断真的掌握

每个主题都用四项证据验收，不用“看过课程”代替：

1. **说清楚**：不用背定义，能解释输入、处理、输出、失败路径。
2. **定位到代码**：找到入口、核心函数、状态保存点和相关测试。
3. **预测变化**：在运行之前，预测消息、数据库记录或外部状态会怎样变化。
4. **动手验证**：完成一个小修改或故障实验，说明结果为什么支持你的判断。

进度可以记成“未开始 / 能解释 / 能定位 / 能修改验证”。最后一项不是要求所有主题都做到，而是按下表分别验收。每个主题先做检查题，已经能答对和做出来的直接跳过。

## 2. 学习顺序与停止标准

| 顺序 | 主题 | 为什么现在学 | 到什么程度即可进入下一项 |
|---|---|---|---|
| 1 | Python 阅读与运行 | 能直接阅读 Voren，而不是逐行翻译语法 | 独立运行一个单测，读懂类型、异常、with、对象依赖；能改一个参数校验 |
| 2 | 单次 Agent 执行 | 所有后续知识的入口 | 手画三轮消息列表，指出模型、工具、Loop、Manager 的职责 |
| 3 | 外部操作与持久状态 | Voren 最值得深入的工程部分 | 解释审批绑定、操作编号、数据库条件更新，以及超时后为何不能盲重试 |
| 4 | 记忆、检索与 Skill | 分清三种数据用途 | 指出当前检索算法；解释版本冻结、候选评测与启用的区别 |
| 5 | 模型 API、评测与基础 RAG | 补齐项目之外的应用知识 | 会分类失败、做小规模对比实验；能实现并评测最小检索练习 |
| 6 | TypeScript/Node.js 阅读 | 进入 RunGuild 的最低语言门槛 | 跟踪一个 async 调用链，读懂接口、联合类型和事务回调 |
| 7 | PostgreSQL 与消息可靠性 | 多 Worker 协作的基础 | 用两个连接解释抢任务、租约、过期执行者和 Outbox 重投 |
| 8 | 代码交付与协作文档 | RunGuild 的交付边界 | 解释提交、测试、评审、集成所对应的版本，分清 Worktree 与沙箱 |
| 9 | 系统设计与复述 | 把零散理解转成面试表达 | 通过一轮项目深挖和一个陌生场景设计，能承认边界并给改进方案 |

不设“几天包会”的承诺。可以把一次学习安排为：先复述上次内容 → 读一条调用链 → 做一个实验 → 记录一个失败原因。当天只推进能验收的内容。

## 3. Python：先学项目使用到的语言能力

**需要补：** list/dict/set/tuple；函数参数与返回值；类、实例、组合与继承；类型标注、Union、Protocol 的作用；异常传播；with 和资源关闭；模块导入；datetime、JSON、hashlib、pathlib；虚拟环境、依赖锁、unittest。

这些概念要落到 Voren：模型返回值怎样成为 ModelResponse；字典怎样经过 Pydantic 校验；异常如何变成运行失败；SQLite 连接在哪里关闭；一个方法为什么把时钟和 ID 生成器作为参数传入。

**优先阅读：** [运行模型](../../src/voren/runtime/models.py)、[动作契约](../../src/voren/adapters/workspace_contracts.py)、[动作网关测试](../../tests/test_action_gateway.py)。

**验收：**

- 给一个参数模型增加校验，写出成功、字段缺失、类型错误和业务约束错误四种输入。
- 能解释“类型标注”和“运行时输入校验”为什么是两回事。
- 用 with 管理临时目录或文件；异常发生后确认资源仍被关闭。
- 在不调用真实模型的条件下，替换一个 Fake Adapter 并运行对应单测。

**暂不必展开：** 元类、高级描述符、C 扩展、解释器源码。遇到项目确实使用的机制再补。参考 [Python 3.12 官方教程](https://docs.python.org/3.12/tutorial/) 与 [Pydantic 模型](https://docs.pydantic.dev/latest/concepts/models/)。

## 4. Agent Loop 与模型接口：必须能够自己写最小版

**需要补：** system/user/assistant/tool 消息、工具定义与参数 Schema、调用 ID 关联、模型响应解析、读取工具与写操作分流、循环终止、步数与工具预算、重复调用限制。

**代码入口：** [AgentLoop](../../src/voren/runtime/agent_loop.py)、[模型适配器](../../src/voren/providers/openai_responses.py)、[脚本模型](../../src/voren/testing/scripted_model.py)。

**验收：** 用预设响应实现“查邮件 → 查日历 → 生成操作提案”的最小循环；打印每轮传给模型的完整消息结构。然后注入未知工具、非法参数、重复调用、空模型响应和超预算，说明系统分别如何结束。

**接口层还要会解释：** HTTP 超时、429/5xx 的分类、带抖动的退避、总截止时间、流式首字时间与完成时间、客户端取消和服务端取消的区别。是否支持某种功能必须查看具体提供商能力，不能把 API 路径兼容当成行为完全兼容。

**停止标准：** 能独立写一个离线工具循环，并知道接真实模型时替换哪一层。无需先学完大型 Agent 框架。

## 5. 审批、幂等和恢复：用具体故障窗口学习

**需要补：** Run ID、tool call ID、operation ID、客户端请求 ID 各自的作用域；稳定操作身份；状态机；审批摘要；比较并更新；唯一约束；同一事务内的状态和事件；外部副作用与本地事务之间的断点。

**代码入口：** [ActionGateway](../../src/voren/actions/gateway.py)、[操作账本](../../src/voren/actions/ledger.py)、[RunManager](../../src/voren/runs/manager.py)。

**至少能够解释四种时刻：**

| 故障点 | 必须查什么 | 不能直接得出的结论 |
|---|---|---|
| 获批前崩溃 | 提案及审批记录 | “模型想执行”等于已获授权 |
| 外部请求发出前崩溃 | 操作状态和实际请求证据 | committing 必然意味着外部已执行 |
| 外部成功后、回执保存前崩溃 | 外部可观察状态和稳定标识 | 本地无回执等于外部未发生 |
| 回执已落库、页面未更新 | 账本和 Run 状态 | 页面没显示成功等于需要再执行 |

**验收：** 对同一操作重复批准时，解释哪些记录复用；用测试演示外部成功但本地超时，恢复时只查询外部状态，不再次发送。说明何时仍然无法判断，需要保留不确定状态。

**必须理解的边界：** SQLite 中的原子条件更新不能为任意第三方 API 提供通用 exactly-once。模型检查点存在，也不意味着所有模型适配器与 Web 路径都能跨进程恢复。当前 Responses 适配器还依赖进程内原始输出缓存，详见 [Voren 解析](01-VOREN-ARCHITECTURE.md)。

## 6. Memory、Knowledge、Skill：按读写来源区分

**需要补：** 用户偏好、执行记录、知识文档、程序性指令四者的用途；哪些内容有指令权限；记录来源、摘要和版本的原因；激活指针与不可变版本；当前上下文与长期存储的区别。

**当前实现要说准确：** Voren 的知识检索是确定性词项匹配，不是已经接入向量库的完整 RAG。Skill 路由比较保守，候选编辑范围受限；评测接受和正式启用是两个动作。工具 scope 兼容性检查不等于操作系统或权限沙箱。

**验收：** 能把“用户说以后会议留 15 分钟间隔”“邮件正文说忽略原指令”“一次执行成功”“会议纪要更新”分别放入正确的数据与信任类别；能追踪新版本从安装到激活再被下一次运行读取的路径。

**需要会改：** 制作一个只改 Skill 指令、保持工具/效果合同声明不变的候选；验证被评测拒绝的候选不能经 promote 路径启用，回滚不能覆盖后来已经生效的新版本。合同不变不代表运行时按 Skill 限制所有工具与副作用，实际集合仍由应用装配决定。还要区分可信操作者的直接安装/激活路径：它没有全局强制复用候选评测门禁。进阶练习可复现当前 diff 行数漏计和 held-out 案例漏登记问题，见 [12 复核记录](12-SOURCE-RECHECK.md)。

## 7. RAG：补应用流程和检验方法

**需要补：** 文档解析与切分、chunk/原文定位、embedding、相似度、稀疏/稠密/混合检索、重排、top-k、上下文预算、回答引用、权限过滤、更新与删除传播。

**验收项目：** 用你自己整理且不含敏感信息的 15—30 段项目说明，准备一组“能回答、无答案、需要多个片段、旧版本容易误导”的问题。先做词项检索基线，再实现一个小规模向量检索版本；保留检索结果和正确片段标注。

**需要算清楚：** 检索是否找到了必要证据，与最终回答是否正确是两个指标。比较 top-k 变化时同时看证据覆盖、噪声、延迟和输入长度，不能只看“回答更长”。小练习的数据量是学习设计，不是已有业务指标。

**停止标准：** 能实现一个最小检索管线、定位检索失败还是生成失败，并解释为什么某些问题应该拒答。先不必自研向量索引、训练 embedding 或完成大型知识图谱。

外部概念与问答依据见 [通用问答](05-AGENT-FUNDAMENTALS-QA.md) 和 [网页来源](09-WEB-SOURCES.md)。

## 8. 评测：先能识别无效结论

**需要补：** 固定配置、基线、候选版本、held-out 数据、样本泄漏、配对比较、任务效用、安全指标、基础设施失败、重复实验、成本覆盖率、模型裁判与程序性 oracle。

**对照当前代码：** Voren 只排除证据显式登记过的 case ID，不会自动识别遗漏登记的原题；raw behavior 强制约束位于 AgentDojo 学习评测入口。RunGuild 冻结数据库中的模型标识，但 Worker 环境变量仍能覆盖有效模型与参数，Scenario 也未完整保存模型/预算及人工介入信息。能指出这些缺口后，再讨论怎样做可复现实验。

**验收：**

- 使用相同任务、模型和预算比较两个 Skill 版本，区分“没有退步”和“已经改善”。
- 故意让一个候选在正常任务更好、攻击场景更差，解释为何不应启用。
- API 超时、Schema 解析错误和真正任务失败分别记录，不能把所有错误归因于模型智能。
- 解释为什么 no_skill 6/6 与 static_skill 4/6 这样的仓库小样本不能推广成“Skill 普遍没用”，也不能包装成正向收益。

**停止标准：** 能设计一张逐案例结果表，清楚说明结论适用范围；能提出下一轮实验会固定哪些变量。统计推断先掌握样本量、波动和置信区间含义，无需从证明统计定理开始。

## 9. TypeScript / Node.js：达到阅读和局部修改的程度

你优先补 Python 是合理的，但保留 RunGuild 项目就需要读懂它的核心调用链。目标是理解该仓库所需的语言范围。

**需要补：** const/let、对象和数组、可选字段、interface/type、联合类型与类型收窄、泛型的基本阅读、import/export、Promise、async/await、try/finally、事件循环、进程与子进程、AbortSignal、npm workspace。

**验收：** 从一个 API 函数走到 Repository 事务，再到 Worker；指出 await 前后可能让出执行的位置。修改一项参数校验或预算规则，跑对应测试；遇到 unknown 必须校验，不用 any 跳过问题。

**容易错的点：** TypeScript 类型不会自动校验网络 JSON；一个 Node 进程使用事件循环也不会消除多进程的数据库并发竞争。CPU 密集任务和同步文件调用可能影响事件循环响应。

**暂不必展开：** React 组件生态、CSS、复杂类型体操。能解释页面提交与后端状态的关系即可。参考 [TypeScript 常用类型](https://www.typescriptlang.org/docs/handbook/2/everyday-types.html) 与 [Node.js 事件循环](https://nodejs.org/en/learn/asynchronous-work/event-loop-timers-and-nexttick)。

## 10. 从 MySQL 迁移到 PostgreSQL 和 SQLite

已有 SQL、索引、事务基础可以复用。需要补的是项目依赖的差异，而不是把数据库课程重新学一遍。

| 数据库 | 在项目里补什么 | 合格表现 |
|---|---|---|
| SQLite | 嵌入式连接、文件存储、WAL、单写者竞争、事务边界、条件 UPDATE、备份和关闭 | 能解释为什么重开连接还能读到 Run；能用两个连接验证操作认领冲突 |
| PostgreSQL | MVCC、默认隔离级别、FOR UPDATE / SKIP LOCKED、RETURNING、ON CONFLICT、JSONB、迁移与索引 | 能解释为什么两个 Worker 不应领取同一 attempt；能读懂该事务更新了哪些表 |
| MySQL | 复习自己工作中实际用过的事务、唯一约束和锁；注意具体版本/引擎行为 | 能把已有经验迁移到新数据库，同时指出哪些 SQL 语法不能直接复制 |

WAL 允许读写更好地并行，但不能据此说 SQLite 普通模式支持多个并发写者。SKIP LOCKED 适合某些队列领取场景，不适合拿来证明查询看到了完整一致的数据集合。参考 [SQLite WAL](https://www.sqlite.org/wal.html)、[PostgreSQL 17 隔离级别](https://www.postgresql.org/docs/17/transaction-iso.html) 和 [SELECT 锁定子句](https://www.postgresql.org/docs/17/sql-select.html)。

**验收：** 用两个会话手画事务交错顺序：读取、加锁、更新、提交、崩溃、重试。再指出数据库锁释放与外部命令停止执行为何不是同一个事件。

## 11. 多 Worker、消息与外部执行

**需要补：** Task 与 Run/attempt 区别；租约和续期；过期执行者的令牌检查；inbox/outbox；至少一次投递与去重；数据库事实与 Redis 通知的职责；轮询补偿、背压、限流和取消。

**验收：** 画出“业务事务提交 → 通知发送 → 消费 → 确认”的崩溃点，解释每处是丢失、重复还是延迟风险。能说明为什么 Redis Pub/Sub 断线后不保证补发，以及为什么 RunGuild 必须依赖数据库记录恢复工作。参考 [Redis Pub/Sub](https://redis.io/docs/latest/develop/pubsub/)。

**需要会改：** 在练习副本中加入一次通知失败，任务仍能经数据库扫描被发现；验证旧 Task token 不能续租、接管后被替换的旧 execution_token 不能提交工具结果。工具 finish 不直接检查到期时间，要把“到期但尚未接管”另列为场景。任务完成与证据写入另查其状态和版本门禁，不预设所有接口都校验同一 token；宿主命令或外部服务也未必已经终止。

## 12. Worktree、测试证据与 Yjs

**需要补：** commit、tree、branch、Worktree；未提交变更；候选合并；测试与具体提交绑定；不可变证据；独立验收 oracle；Yjs 更新、持久化、同步、固定版本。

**验收：**

- 分别解释“测试过的版本”“评审过的版本”“最后合进去的版本”怎样相互对应。
- 说明修改源文件后为何不能复用之前的测试通过记录。
- 构造两个分别测试通过但合并后失败的分支，证明集成候选也要验证。
- 说明 CRDT 处理协同更新，不会证明内容正确、审批有效或业务权限合法。
- 解释 Git Worktree 共享同一主机资源，无法阻止仓库脚本访问宿主网络和文件。

参考 [Git Worktree](https://git-scm.com/docs/git-worktree) 和 [Yjs Document Updates](https://docs.yjs.dev/api/document-updates)。

## 13. Python 异步与 Web：不要把 async 当成性能承诺

**需要补：** 协程、await、任务并发、取消传播、阻塞 I/O、线程与进程；请求生命周期、后台任务、SSE 事件与 token streaming 的区别；错误码、幂等请求、状态查询。

**验收：** 写一个两个并发只读请求的练习，带总超时、并发上限和 finally 清理；解释客户端断开后，外部工具是否必然停止。再对照 Voren 当前同步 submit 路径，指出多用户化改造应从任务排队和状态 API 入手，而不是只把 def 改成 async def。

参考 [Python asyncio 任务与取消](https://docs.python.org/3.12/library/asyncio-task.html)、[FastAPI 并发说明](https://fastapi.tiangolo.com/async/)。

## 14. 算法、训练和框架学到哪里

| 方向 | 本次优先掌握 | 当前可以延后 |
|---|---|---|
| 数据结构与算法 | dict/set 去重、队列、DAG 拓扑排序、环检测、LRU 基本思想、时间空间复杂度 | 竞赛型动态规划和与岗位无关的偏题 |
| 模型原理 | Token、embedding、attention 的作用、上下文长度、预训练/SFT/RL 的区别 | 推导完整训练算法、分布式预训练 |
| 微调 | 数据质量、何时用 SFT/LoRA、与 RAG/提示工程的区别、评测和维护成本 | 把未执行的训练写成项目经验 |
| 框架 | 理解状态、图、工具、checkpoint 的抽象；能比较手写与框架接入成本 | 为面试同时重写 LangChain/LangGraph/AutoGen 等多个版本 |
| 运维 | 日志、进程、环境变量、容器基本隔离、健康检查、部署回滚 | 先学完整 Kubernetes/服务网格再回到项目 |

这些是学习范围建议，不是对所有招聘岗位的统一要求。具体 JD 若要求向量搜索、模型微调或框架开发，再调整深度。
