# 2026-09-16 执行恢复修复

本轮修复三个代码审查发现，不把外部真实账号运行或模型质量纳入结果声明。

## 模型步骤重放

Transcript v2 在写入 `model.responded` 事件之前保存加密的模型响应；读取结果也先保存，再发布 `tool.observed` 事件。步骤中断后使用原响应和已保存的观察结果，按步骤开始时的状态重建调用计数，不重新调用模型或重复已经保存的读取。下一步骤的检查点完成后，清除待重放数据。

v1 检查点仍可读取，并保留原摘要算法。旧版本已经遗失的响应不能凭空恢复。模型请求成功但响应尚未持久化的窗口也不承诺供应商请求 exactly-once；读取结果尚未持久化时，只读工具可能重读。

## Web 审批恢复

Web 根据持久动作状态选择继续派发、读取已存回执或仅观察核对。重试必须匹配原决定 ID、Proposal Digest 与批准值，复用原审批时间，不能通过重试延长有效期。`committing` / `ambiguous` 状态不重新派发。

真实供应商适配器可在重启后重新连接；内存 AgentDojo 工作区丢失且没有可用终态回执时仍拒绝伪装恢复。页面提供“重新核对结果”，沿用原决定，不产生第二次外部写入。

## 验证失败的再次核对

只缺少可见结果的 `verification_failed` 可重新观察；核对通过后完成 Run。曾观察到额外或不匹配副作用的失败保持待人工核查，后续干净观察不能抹去违规事实。被替换的回执在同一 SQLite 事务中归档至 `operation_receipt_history`，不会丢失最初失败记录。

## 验证

- `tests/test_transcript_recovery.py`：响应落库后、响应事件后、读取事件后的中断与重建，恢复后立即取消时保留已消耗的模型预算，以及 v1 摘要兼容。
- `tests/test_action_gateway.py`：延迟可见性、回执归档、额外副作用不可被后续结果洗掉。
- `tests/integration/test_web_app.py`：审批落库、外部提交前后回执窗口的重启、不同决定拒绝、同决定核对且仅一次写入。
- 全量命令：`python -m unittest discover -s tests -q`。环境依赖使用 `pylock.toml`，HTTP/MCP 测试需要本机 IPC。

全量验证额外发现评测审批采用注入时钟、动作网关使用系统时钟的问题；已让评测中的 RunManager 与 ActionGateway 共享评测时钟，避免日期变化使确定性用例出现审批过期。
